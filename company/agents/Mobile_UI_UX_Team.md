## Current assignment

Build the LindaData HQ into a better-than-Jira mobile-first operating system.

## Phase 1 — Mobile-first foundation

Required now:

- No desktop-only board squeezed onto iPhone.
- Main board usable one-handed.
- Bottom nav with the most important views only.
- Cards readable without opening every issue.
- Issue drawer opens as a mobile bottom sheet.
- Create/edit issue works on iPhone.
- Card movement works with tap buttons, not only drag-and-drop.
- Sync state is visible and honest.
- Local save is clearly labeled as local, not final.
- GitHub sync is deliberate and visible.

## Phase 2 — Better than Jira

Target differentiators:

- AI-assisted work packets from messy CEO instructions.
- Agent routing built into every issue.
- Every issue has executive owner and specialist agents.
- Built-in review-layer proof requirements.
- Mobile review notes become work items.
- One-tap CEO status summary.
- Project cards show next decision, not just status.
- Fast morning mode: only what matters today.
- Founder energy and noise reduction built into the UI.
- GitHub-native proof trail.

## Design principles

1. iPhone first. Desktop expands the experience later.
2. Every visible button must work exactly as labeled.
3. Do not show controls that cannot persist or produce proof.
4. Prefer short labels and obvious actions.
5. Keep the CEO out of implementation weeds.
6. Every card should answer: what is this, why now, who owns it, what is next?
7. Review happens inside the real app screen, not in a detached workspace.
8. Local state is temporary workspace state; durable work is GitHub-backed.
9. Avoid walls of text. Expand details only when opened.
10. Keep private details public-safe on GitHub Pages.

## Mobile QA checklist

Before any HQ/Jira change is called ready:

- Loads on iPhone Safari.
- No horizontal scroll required for the primary workflow.
- Top nav does not hide the main action.
- Bottom nav is reachable by thumb.
- Create issue is visible and easy.
- Issue drawer is not trapped behind Safari bottom bar.
- Inputs are large enough to tap.
- Card move works without drag-and-drop.
- Search and filters work.
- Reports are readable on narrow screens.
- Export/import do not pretend to be cloud persistence.
- Sync failure preserves text and says what happened.

## Acceptance criteria for current HQ work

The mobile HQ is acceptable when:

```text
Open HQ on iPhone
→ see board immediately
→ create an issue
→ move it between lanes with taps
→ edit details
→ add checklist item
→ add comment
→ see it marked unsynced
→ sync it to GitHub inbox or see an honest failure
→ return to board without losing work
```
